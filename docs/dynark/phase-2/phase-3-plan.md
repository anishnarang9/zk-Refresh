# Bounded Phase 3 plan

Originally drafted while Phase 2 was running, without an execution grant. The user's October 14 [engine-focus authorization](engine-focus-oct14.md) now permits independent early witness work before Phase 2 closes. Each compiler acquisition, prototype and paid experiment still requires a concrete reviewed scope and finite execution budget. Finalize product defaults against the completed Phase 2 measurements. Preserve the accepted controlled-organization CA, signed organization/group/purpose fields, local native proving, exact work-request action, stale-issuer pause and strict execution-current-root policy.

The first engineering experiment should test whether unchanged-circuit same-action witness work can be reused safely. It must not alter the circuit, public statement, setup, Groth16 reduction or validation policy to manufacture a gain. Real-profile qualification is a separate bounded specification task; neither requires reopening the chosen product direction.

1. **Freeze inputs and dependency evidence.** Review final Phase 2 source/artifact identities, exact full-witness baseline and losses. Identify the precise compiler/source/flags and an executable dependency representation for the current witness program. R1CS adjacency and symbol names alone are insufficient to certify witness-generation dependencies. Describe stable versus root/path-dependent operations and all dependencies crossing that boundary. If the available compiler artifacts cannot support that argument, report the missing evidence and retain full witness generation; do not infer an incremental schedule from observed changed coordinates alone. Initial output is one reviewed design and experiment record, with no setup or circuit changes.
2. **One falsifiable prototype after design review.** Delegate implementation to Sol high, with a separate Sol medium measurement worker only when ownership permits. Restrict the first candidate to existing same-action synthetic near/middle/far and serial fixtures. Compare every canonical assignment coordinate against a newly generated full witness, validate the entire unchanged relation and exact expected public statement, and independently verify ordinary proofs. Include no-op, reverse/cancellation, invalid path/own revocation and new-action invalidation. Any unsupported dependency or input falls back before reusing stale intermediate state. Keep the current full-satisfaction policy until a separate completeness proof and adversarial gate justify an incremental validator.
3. **A paid complete-refresh comparison.** After exact equality, charge cache construction/loading, witness work, validation, deltas, selected proof mode, maintenance, writes/reload, failed work and retained memory. Use the same key/reduction and both the improved ordinary comparator and measured Phase 2 update paths. Counterbalance order and preserve individual samples. Accept a scoped negative result if preparation/retention erases the warm benefit; do not equate changed-wire count with computational savings or assume hundreds of retries.
4. **Freeze the real credential qualification specification.** Document exact signed field/OID encodings, DER and chain bounds, RSA algorithm restrictions, holder signer interface, issuer-version/rotation semantics, authenticated status source/cadence/timeout, request digest/replay domain and supported laptop budget. Use public or explicitly authorized synthetic corpus items only. Record positive/negative corpus requirements and which values must be proved from signed bytes. This is specification work, not permission to read real holder credentials or keys, change the current circuit, contact an operator or deploy a service.

Initial resource policy: at most two coding workers, one explicitly named heavy execution owner, four Rayon threads and two build jobs unless a new experiment justifies different settings. Prototype small tests use a 15-minute/2-GiB RSS/2-GiB incremental-artifact ceiling. Any compiler rebuild or actual credential measurement requires its own pre-recorded finite runtime, memory, storage and operation budget derived from Phase 2 observations. Do not inherit a small-test ceiling blindly or loosen a failed cap. Hash and preserve original inputs; place secret-bearing intermediate state and logs in protected ignored storage; publish only scrubbed aggregate evidence. Small reviewed local commits remain separate from any future authorization to publish.

Exit from this first Phase 3 slice requires a complete dependency argument, exact full-witness equality on the supported corpus, explicit invalidation/fallback behavior, independently verified proofs and paid complete-refresh/session results. Registry services, production key service, original-zkey adapter, Solana/application execution and real credential deployment remain separate gates. No production security or whole-profile generalization follows from a successful synthetic prototype.
