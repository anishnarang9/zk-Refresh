## 1. Scope, disposition and concrete hazards

Read complete `persistence-design.md`, `architecture.md`, `conformance.md`, the T6 plan, complete `evidence/t5-state-layout.md`, current T1/T2 private types and emerging T5 `reconstruction.rs`/`dynamic.rs`. The existing write/sync/publish/directory-sync-before-external-CAS ordering is appropriate. Keep it. Adopt a full partial-builder record rather than silently discarding partial work on reload. Freeze the actual T5 schema before implementing the codec.

Required design decisions before dispatch:

| Priority | Hazard | Required contract |
|---|---|---|
| P1 | AEAD/MAC plus a local generation cannot reject whole-store rollback | Expected exact commit, session epoch and key access live outside the replaceable directory; an in-memory provider gives process-lifetime protection only |
| P1 | Provider timeout may occur after trust advanced | CAS returns committed/conflict/unknown; unknown retains both files, blocks further writes and resolves by an authoritative read or explicit recovery/rebuild |
| P1 | Revocation racing a save can resurrect the session | Invalidation, key leasing, nonce reservation and commit CAS share a linearizable session-epoch fence; invalidated tombstones cannot become empty/active again |
| P1 | Current proof plus q vectors omit partial builder state | Persist the complete closed state graph and exact cursors/role mapping; never persist an in-flight target/journal or label a reset builder as resumed |
| P1 | Authenticated producer bytes can still encode bad counts/roles/cursors | Bounded decode, canonical fields/points and complete engine invariants after authentication; authenticated does not mean structurally valid |
| P1 | Concurrent recovery may finish loading an obsolete commit | Recheck provider exact commit/epoch after decode; return a fenced handle, with use subject to current provider/application policy |
| P2 | Maintenance does not advance witness generation | Separate monotonically increasing persistence revision from witness/current/anchor/builder generations |
| P2 | Ordinary compressed projective encoding changes physical representation | Parent chose exact point/field/metadata equivalence; do not claim X/Y/Z equality, and charge conversion work |
| P2 | Serialization/reload can duplicate hundreds of MiB of secrets | Preflight complete live capacities, one in-place envelope buffer, decoded pool, assignments/maps, journal initialization and public material |

No T1/T2 token chain or E2 checksum is durable authentication. Legacy adoption first needs the externally authenticated exact-cache/package/witness/public/session context already required by T2; only an authorized validated producer can enroll that state in T6.

## 2. Proposed bounded envelope and dependency recommendation

Use one immutable file `commit-<32-byte lowercase-hex-id>.dync` under a private session directory. The filename is constructed from the trusted ID, never accepted as a path supplied by the header. Proposed v1 framing: **1024-byte fixed header, exact payload-length ciphertext, 16-byte detached tag**. All integers have fixed-width little-endian encoding; all enum tags have explicitly assigned values; reserved header bytes must be zero. No compression, optional extensions, unknown sections or trailing bytes in v1. Header layout/offsets must be frozen with a golden fixture before implementation.

The entire 1024-byte header is AEAD associated data, prefixed by the fixed protocol string `dynark-bn254/persistence-envelope/v1`. It contains:

- magic, envelope version, private-state schema version, algorithm/encoding identifier and header size;
- all five `PackageIdentity` digests: matrix, circuit, proving key, verifying key and package;
- trusted R1CS/executable/profile/public-schema commitments, fixed BN254/Groth16 curve identifier, exact reduction, domain/root convention and all five `Shape` sizes;
- exact public updating/reconstruction-material commitments and reconstruction algorithm/unit version, so a table/cursor convention change is not interpreted under an old schema;
- credential/holder binding, action binding, issuer-policy scope commitment and provider session ID;
- session epoch, key epoch/key ID, persistence base revision and new revision, base commit ID and new commit ID;
- current witness generation and active/builder snapshot generations, explicit state mode, plaintext length, ciphertext length, total file length, and 12-byte nonce.

All these are public metadata; their visibility and file sizes leak session linkage/shape/progress. AAD provides no confidentiality. Do not put raw support locations, witness hashes useful for guessing low-entropy values, blinders or private counters beyond agreed public metadata in it. The provider's registered context must match the caller's trusted package/manifest, not a context reconstructed from attacker header claims. Public schema names and PK/UK/matrices remain shared public artifacts outside the encrypted record.

Recommend evaluating **`aes-gcm-siv = 0.11.1`, Aes256GcmSiv**, with detached `AeadInPlace::{encrypt_in_place_detached,decrypt_in_place_detached}`. Locally cached authoritative source confirms a 32-byte AES-256 key, 12-byte nonce, 16-byte tag, plaintext/AAD limits `2^36`, and no ciphertext copy required by detached slice operations. Engine limits must be much smaller and checked independently. Features should omit crate RNG convenience paths: propose `default-features = false`, `features = ["aes"]`; nonce/key generation stays with the fallible caller/provider contract. Parent must review the resulting exact lockfile/license/features/transitives before approval; nothing was installed or changed here. Existing registry availability is not dependency approval. Source is MIT OR Apache-2.0. [Versioned crate documentation](https://docs.rs/aes-gcm-siv/0.11.1/aes_gcm_siv/), [RFC 8452](https://www.rfc-editor.org/rfc/rfc8452).

Misuse resistance does not authorize fixed/reused nonces. Use fresh fallible nonce acquisition for **each encryption attempt**, including retries, orphans and failed CAS attempts; the provider additionally prevents reuse under a key epoch as specified below. Do not reuse proof-r/s bytes, a rolled-back counter, truncated commit ID or RNG state serialized in the cache. RFC 8452 recommends random nonces and requires withholding decrypted plaintext until authentication succeeds. Its example quantitative message bounds cannot simply be copied for this longer AAD/custom usage. [RFC 8452, sections 5 and 9](https://www.rfc-editor.org/rfc/rfc8452).

The versioned crate docs state that the crate itself has not been audited and describe hardware/portable constant-time prerequisites. This is a material dependency limitation, not a production audit claim. Source zeroizes intermediate key derivation arrays, but that does not establish master-key schedule erasure or engine secret erasure. Consider explicit `aes/zeroize` feature unification and a direct already-locked `zeroize` use for owned keys/byte buffers only after parent feature review; inspect the resolved backend and lockfile rather than assuming transitive feature activation. [Crate security documentation](https://docs.rs/aes-gcm-siv/0.11.1/aes_gcm_siv/).

## 3. Full private schema and invariant checks

Save only a quiescent complete T5 committed root while holding its serial owner. `Busy`, nonempty journal, set first-touch marks, staged target, cancellation/rollback in progress or a pending transaction rejects the checkpoint. A committed partial **maintenance builder** is allowed. It must not be confused with an in-flight target transition. No journal/preimages, pending transaction, secret RNG state, mutable alias or pointer is serialized.

Use a fixed ordered section directory inside the encrypted payload: mode/root, assignments, physical pool, role map, active correction maps, builder, current raw proof, scheduler/accounting. Section count is fixed by schema/mode; sizes use checked fixed-width counts. A scan of authenticated bytes must verify all lengths/offsets/count products, aggregate requested allocation/work and exact EOF before any engine vectors or group objects are allocated. No generic derive-deserializer that allocates from wire counts.

| Section | Required state and validation |
|---|---|
| Root/mode | Full `PackageIdentity`, provider context, exact root/token, current generation/public statement, mode `DynamicReady`/`FullOnly`/supported `PendingPreparation`; all duplicated header metadata must match |
| Assignment graph | Each actually retained opaque assignment exactly once, stable small object IDs and explicit references preserving aliases; no staged target. Emerging source retains only Current.assignment; do not add active/frozen witness copies solely for persistence. If final T5 adds references, bound distinct objects by its frozen schema, each exactly v canonical Fr, coordinate one and exact publics/full satisfaction; additional objects require a schema/budget amendment |
| Physical pool | Four G1 physical vectors and six Fr vectors, each exactly N when initialized; slots stored once independent of active/build roles. Save every initialized mathematical group point and Fr value, including stale scratch and post-promotion recycled values. If T5 permits partial initial allocation, store its exact initialized prefixes and readiness status; absent cells may never be read and reload initialization costs are charged |
| Role mapping | `active_g[2]`, `build_g[2]` are a permutation of slots 0..3; analogous field row roles cover 0..3; FFT field work slots 4/5 fixed in current source. Source rows must match active row slots. References have checked ranges and no prohibited aliasing |
| Active metadata/maps | Exact active snapshot generation/distance/token and an assignment reference only if retained by T5; complete active projections and rows; normalized alpha/beta to current witness, each sorted unique domain index, nonzero canonical Fr and bounded support. Numeric state agrees with its named generation |
| Builder | Frozen generation/distance/token, source slot IDs, frozen assignment reference if retained, immutable overlays, post-snapshot pending eta/theta and their exact through-current generation namespace; preserve empty maps, alias relationships and exactly-once application state |
| Cursor | Stable phase enum including distinct `InitialReadyAlias`, completed actions, stream, index, stage, overlay cursors and initialization/valid prefixes. Current `Cursor` has phase/done/stream/index/stage/overlay. Recompute allowed phase ranges and completed-action count from the frozen schedule; reject impossible combinations before a step can index/shift |
| Raw/current proof | Current validated assignment/public values, A-G1, B1-G1, B2-G2, C-G1, retained independent r/s and complete output proof, current token/generation. These are private state, even if an ordinary proof is public elsewhere |
| Scheduler/configuration | Exact DynamicConfig threshold, cap policy and all bounds, b, t, accepted cumulative distance C, cycle origin, active/builder/current distances, credit/overshoot, completed work and full WorkLedger required by T5. Checked b>0, 0<=t<b, W matching the algorithm/N, done<=W and generation/distance ordering. Effective limits must also obey independently supplied reload policy; stored values cannot raise caller caps. A stricter incompatible policy rejects/rebuilds, never silently changes threshold/units. Cancellation cannot refund C; authenticated counters are not proof of an entire history |

`InitialReadyAlias` remains distinguishable from a completed reconstruction of a distinct snapshot even if its `done` is W. `FullOnly` contains no usable stale q/builder/correction maps, and returning to dynamics is an explicitly charged preparation route. Persist optional preparation only after its actual initialized-prefix schema is frozen; otherwise reject saving that mode with a typed unsupported-mode error rather than invent readiness. A separately explicit `RebuildRequired` record may be supported, but is never a successful partial resume.

**Parent disposition: canonical compressed G1/G2 encoding and canonical Fr encoding.** Preserve every initialized buffer's mathematical group point, every Fr value, all roles/maps/cursors/tokens/generations, and all pending/frozen state. Do not persist raw Rust memory, Montgomery limbs or custom projective-coordinate triples. Pinned `ark-ec 0.5.0` canonical projective serialization converts through affine; reloading normalizes X/Y/Z, so the persistence contract expressly does not promise those triples remain identical. This is sufficient for the resumed algebra under group-point equivalence. T5's exact in-memory undo of pre-call cells remains unchanged. Canonical compressed bytes, field values and metadata provide the round-trip comparison oracle; resumed raw components are compared as group elements under common test r/s, followed by ordinary proof verification.

Assign this canonical-point codec its own fixed version; verify canonical field/point encoding, curve and subgroup validity under the pinned backend after authentication and structural preflight. Reject alternate/noncanonical encodings by canonical re-encoding comparison where the deserializer alone does not enforce uniqueness. No unchecked deserializer or malformed point may reach proof/reconstruction arithmetic. Normalization/inversion, point decompression/subgroup checking and any batching scratch/work are charged and measured. Do not call unbounded `Valid::batch_check` on the entire pool: its implementation collects and normalizes a new vector; use explicitly bounded chunks or per-cell validation with a charged work cap. No serialization size/speed improvement is claimed as an observed outcome.

At the last source inspection, `Root` is Current/optional Active/optional Builder/Roles/t/distance, `Current` owns one assignment plus binding/A/B1/B2/C/r/s, and `DynamicState` owns config/optional Pool/Journal/pending/WorkLedger. `Builder` freezes rows by source slots and immutable overlays, not another assignment. Preserve this representation and map aliases; do not invent historical witness retention or a transition log. `DynamicPreparation` separately has pool lengths, position/total and marks initialization; support it only through an explicit tagged schema after freeze. Internal codec access must not expose public raw-state serializers or unchecked constructors.

After authentication and structural preflight: create retained assignments only through internal full validation; recompute current A/B row evaluations and check active-row-plus-map equality with current rows, plus frozen/materialized relationships wherever enough data remains; check A/B1/B2 against current assignment/blinders and independently verify the current ordinary proof/public statement; compare exact stored tokens with the authenticated root. Current dynamic token chains include previous-token/delta context that is not retained, so do not falsely claim to recompute them from a final snapshot or add a history solely for that check. Their persistence authenticity comes from AEAD plus exact trusted envelope/context. Validate scheduler roles/cursors before any resumed step. Group/proof validity does **not** prove that arbitrary q/partial FFT cells were honestly computed. Trusted validated writer provenance plus AEAD/provider binding is the retained-projection boundary; exhaustive recomputation on cold reload would be a separately charged diagnostic mode. A valid tag cannot repair a buggy producer. Legacy projections still require the T2 external context before first save.

## 4. External key, trust and invalidation provider

Proposed conceptual operations, not a code interface:

1. **Read(session):** authoritative, authenticated, linearizable snapshot of registered public context, durability capability, session epoch/status, allowed key epochs and `ExpectedCommit` or explicit authorized initial state. ExpectedCommit contains revision, ID, exact envelope SHA-256, key epoch, current witness generation and root/schema identity. A missing/unavailable provider is not an empty provider. A durable invalidation tombstone is not bootstrap authorization.
2. **Lease key(session, epoch, key ID):** expose a bounded secret-key lease to AEAD, never a key in logs/filenames/header or a persisted plaintext key. Key ID comes from the trusted expected/proposed provider state. Caller header data must not select an arbitrary fallback key. New per-session 32-byte keys use fallible secure entropy and a provider-generated epoch; no circuit hash/password/blinder as key. Rotation/re-enrollment changes the epoch and cannot erase invalidation history.
3. **Reserve encryption attempt:** fresh nonce bytes via fallible caller `try_fill_bytes`, plus fallible 32-byte commit-ID bytes as a separate request. Provider rejects/retries a reused (key epoch, nonce) under a bounded retry policy, consumes the reservation permanently even on failure and bounds attempt/key lifetime. Synthetic tests may use a protected set. A durable backend must provide durable uniqueness or fresh protected one-use keys per attempt; a local cache nonce ledger does not qualify. Random 96-bit sampling alone gives a collision probability, not a strict uniqueness guarantee. Provider-managed uniqueness storage/cost is explicit; exceeding its bound rotates a key or errors before encryption. No implementation of that durable service is implied here.
4. **CAS(expected, proposed, session epoch):** one atomic check of full expected commit/revision/epoch/context and Active status, then an authenticated durable new trusted record. New persistence revision is exactly old+1 with checked overflow; witness generation may remain equal for maintenance, but may not move backwards. Genesis uses explicit authorized enrollment and a distinct absent-commit marker, never an invalidated tombstone. Commit-ID collision/existing file rejects before mutation. Same commit retry is idempotent only for the same exact envelope digest.
5. **Invalidate(expected epoch, reason/scope):** atomically fence the session, advance invalidation epoch and retire key access/leases as supported. Reasons include own revocation, issuer disablement and action completion; issuer hooks invalidate all registered sessions in that issuer scope. CAS and nonce/key operations observing the stale epoch fail. Re-enrollment is a separate caller-authorized validated rebuild under a new session epoch, never a stale writer's CAS.

CAS outcomes are `Committed(exact receipt)`, `Conflict(authoritative current state)`, `UnavailableBeforeAttempt` when the backend can guarantee no attempt occurred, or **UnknownOutcome**. A timeout/disconnect after dispatch is unknown unless the provider proves otherwise. Read back: exact proposed ID/digest/epoch means it committed; exact old expected state means this attempt did not commit *only when the provider can definitively resolve that operation*, and another current ID means conflict/supersession. Otherwise freeze writes and return an unresolved recovery requirement, keeping both files. Do not create a second concurrent retry operation while the first may still commit. An operation token/idempotency contract must permit definitive resolution.

Synthetic provider tests can model monotonic trust independently of resettable cache storage. They demonstrate the contract, not a durable OS key-store/remote integration. A process-only provider must advertise its capability and cannot advertise restart rollback rejection. Restoring cache plus equally rollbackable provider defeats freshness. Durable implementations must also protect provider state/authentication against rollback, restore attacks and split-brain; persisting the expected ID beside the cache is insufficient.

Invalidation must fence resident use as well as saves/recovery. Serialize local invalidation notification with the state owner; revoke/fence stale handles and clear private state/key access as supported. Provider status/epoch checks are required at output/use boundaries according to its lease contract. An external event can occur between a check and use: strict issuer status, current root, action completion/replay and holder authorization therefore remain fresh application/execution checks. Do not claim distributed instantaneous revocation from local erasure or a cached Active read.

## 5. Transaction, concurrency and recovery procedure

### Concrete safe Unix filesystem recommendation

**Parent disposition:** recommend cached `rustix = 1.1.5` with only `std` and `fs` features (`default-features = false`, `features = ["std", "fs"]`), subject to parent dependency/lock review preserving all existing dependency versions. Its public functions are safe Rust; crate `#![forbid(unsafe_code)]` needs no exception or local unsafe syscall wrapper. Prefer this one small syscall interface over path-based operations plus a broader filesystem abstraction. Locally inspected source supports the following on macOS, as well as the corresponding Linux primitives; no host syscall test was executed here. [Versioned safe openat API](https://docs.rs/rustix/1.1.5/rustix/fs/fn.openat.html).

- Start with a caller-approved held directory descriptor anchored outside untrusted path resolution. Open each necessary directory component with `rustix::fs::openat(parent_fd, single_component, RDONLY|DIRECTORY|NOFOLLOW|CLOEXEC, ...)`, and `fstat` the opened directory for expected owner/type/restrictive mode. Reject `.`, `..`, absolute paths, separators and NUL in component inputs. `NOFOLLOW` only protects the final component of an individual open; never pass an arbitrary multi-component path and call that a complete no-follow policy. Create a missing private child with safe `mkdirat` mode 0700, then open/validate it using the same rules.
- Create the generated temporary basename with safe `openat(session_dir_fd, temp_basename, WRONLY|CREATE|EXCL|NOFOLLOW|CLOEXEC, mode0600)`. The descriptor can be moved safely into `std::fs::File` for bounded writes. Check its type/owner/mode and record device/inode; write/sync and close before publication. An existing temp path, including a symlink, is a bounded collision/error, never opened with truncation.
- Publish with `rustix::fs::renameat_with(session_dir_fd, temp_basename, session_dir_fd, final_basename, RenameFlags::NOREPLACE)`. Cached Apple types map `NOREPLACE` to `RENAME_EXCL`; its backend uses `renameatx_np`. On systems where that call is unavailable, the flagged fd-relative operation returns `NOSYS` rather than silently using overwrite-capable rename. Propagate unsupported/error before CAS. Use the same held fd for both names; never call plain `std::fs::rename`/`renameat` as a fallback. The final path may not replace any existing entry, including a symlink or directory.
- Reopen the published basename using safe `openat` with `RDONLY|NOFOLLOW|CLOEXEC`, `fstat` regular type/owner/mode/device/inode/length, and verify exact envelope bytes against the already computed digest under the bounded reader policy before CAS. A source-name substitution could otherwise publish a different inode after the producer closed it. This verification adds an explicit bounded read/hash cost. Then `rustix::fs::fsync(session_dir_fd)` establishes the required publication-directory barrier before external CAS. Cleanup uses `unlinkat` under the same held fd and the provider fence, then its separately reported directory sync.

Safe `linkat(session_dir_fd, temp, session_dir_fd, final, AtFlags::empty())` is a possible no-replace publication alternative: a pre-existing destination fails instead of being overwritten. It leaves two names until a separate unlink, so prefer the single no-replace rename above on the selected host and do not add an independent fallback path without its own fault tests. `std::fs::hard_link` with path strings by itself does not anchor parent traversal. A held directory fd prevents operations being redirected by later parent-path substitution; it does not prevent a same-user/privileged store attacker from renaming that directory, modifying its entries or corrupting bytes. Such attacks must yield authenticated rejection/missing-file rebuild, not alternative-file selection; availability is not guaranteed against them. Re-establish the approved anchor safely on restart. Advisory locks alone do not authenticate that anchor or defend a malicious writer.

**Sync-strength tiers accepted by parent:** the required Phase 2 baseline records successful file sync and held-directory sync and tests process-interruption recovery on the exact host/filesystem; it makes no unqualified media/power-loss guarantee. For an explicitly requested stronger macOS media tier, safe `rustix::fs::fcntl_fullfsync` is available and the worker must freeze/record the supported file/publication-barrier sequence and test its capability before CAS. The rustix fsync documentation expressly says ordinary macOS/iOS fsync alone does not ensure persistent media; Apple's F_FULLFSYNC requests a device-buffer flush but is filesystem/device dependent. Do not require unsupported directory F_FULLFSYNC for the baseline. If the requested stronger tier cannot be honored, return typed `DurabilityUnsupported` before CAS rather than silently reporting that tier. Record exact sync calls/capability in each result. Production durable-provider qualification remains separate, and storage damage after trust advancement still returns rebuild under the baseline contract. [Rustix versioned fsync source documentation](https://docs.rs/rustix/1.1.5/src/rustix/fs/fd.rs.html), [Apple F_FULLFSYNC documentation](https://developer.apple.com/library/archive/documentation/System/Conceptual/ManPages_iPhoneOS/man2/fcntl.2.html).

**Checkpoint is distinct from a witness update.** T5 may already have a complete committed in-memory state newer than the durable checkpoint. A failed checkpoint leaves that live state valid but explicitly not newly durable; it does not roll T5 backwards. APIs report both live generation and durable receipt. If an API promises a proof/state is durably committed before release, it must withhold that result until this transaction commits, and preflight any separate staging memory needed. Do not hide that distinction or serialize an unfinished T5 target/journal to solve it.

Required save ordering:

1. Hold the serial owner/immutable snapshot lease, reject busy state, read exact provider expected/context/epoch, validate complete candidate and work/size/capacity bounds, reserve all bytes/results and encryption materials. No N-scale private clone is hidden in the snapshot lease; retain exclusive ownership while encoding or explicitly charge a clone. Freeze the candidate root and provider operation ID.
2. Encode once into a bounded owned plaintext buffer; verify final size equals preflight; encrypt in place with the complete AAD and detached tag. All validation, RNG, encoding, digest, allocations and fallible candidate installation preparation precede CAS. The producer performs no secret scalar/value logging.
3. Create private temp in the same directory using exclusive creation, restrictive mode 0600, no symlink following, and validated directory ownership/mode 0700. Write header/ciphertext/tag fully, file sync, close. No plaintext temporary file. Bound path names/read/write counts; use directory-relative handles where available to avoid path substitution. Fail on unsupported security/durability primitives rather than silently weakening them.
4. Atomically publish the unique final name **without overwriting an existing final file**, then synchronize its directory. Platform rename-overwrite behavior is insufficient by itself; select/test a no-replace publication primitive. Retain the old expected file. Failed publication/sync never calls CAS. The new file is an orphan until trust commits. SHA-256 of exact envelope bytes belongs in proposed ExpectedCommit.
5. CAS exact expected to proposed under the same session epoch. After acknowledged irreversible trust advance, only infallible local root/receipt installation may determine success; preallocate it. No verifier, entropy request, allocation, fallible fsync or cancellation/failure hook after CAS may turn a committed result into an ordinary failed save. If the process dies, recover by the trusted new ID. Return `Committed` even if subsequent cleanup fails; report cleanup separately. An unknown outcome follows the fenced-resolution rules above.
6. Optional cleanup may retire obsolete files after definite success, with separate directory sync/cost. Keep at least the new expected file; no uncommitted writer may delete the old expected one. Serialize cleanup with a provider fence/lease or retain all files until a separately authorized safe cleanup, so a stale cleaner cannot delete a concurrently committed file. Bound orphan counts/disk use; exhaustion errors, never deletion of the last trusted file to make room. Unlink is not secure erasure.

Concurrent writers may each publish distinct orphans from the same base; only one full CAS wins. The loser cannot replace/truncate the winner, return its proof as durably committed, retry from an inferred filename generation or delete files named by another provider receipt. Concurrent maintenance at the same witness generation still races on persistence revision. Prefer a single local session writer; external CAS remains the cross-process fence.

Recovery:

1. Read provider expected/context/epoch/status. Invalidated returns invalidated; missing expected/key/file returns explicit rebuild; transient provider unavailability returns an unavailable/fenced recovery result, never fallback. Read only the exact committed filename with no symlink following and regular-file/length checks.
2. Read the fixed header into bounded stack storage. Reject unknown version/algorithm/schema/reserved bytes, wrong complete identity/holder/action/epoch/commit/revision/generation, impossible dimensions or oversized/overflowed declared lengths **before payload allocation/group work**. Header claims are still unauthenticated and can only restrict work, never expand caller caps. Require total file length =1024+payload+16, captured same-handle reads bounded to that length with exact EOF; reject shrink/growth/trailing data. Do not hash one path then reopen to decode another.
3. Allocate only the bounded encrypted payload buffer and read exact bytes/tag; compare the exact received envelope digest with provider expectation. Authenticate complete AAD/ciphertext. The decrypting byte buffer is quarantined: AES-GCM-SIV source decrypts before tag comparison and re-encrypts on failure, so **no parsing, fields, groups, public result, log or callback sees it before success**. Failure discards/zeroizes it best effort and returns explicit authentication/rebuild failure. Digest is an additional exact-ID check, not a substitute for AEAD.
4. Preflight authenticated payload section counts and aggregate decode/work capacities without objects; decode canonically into a new quarantined state and perform section 3 invariants/ordinary verification. Require exact consumed payload EOF. Free/zeroize byte-buffer capacity and unused private objects as supported; no secret dump on typed error. Header authentication does not require trusting wire counts or authenticated invalid points.
5. Re-read provider and require the same exact commit/digest/epoch/status after validation; a concurrent new commit/invalidation prevents release. Install a fenced session handle/receipt only after complete validation. Never scan latest timestamps, maximum generation, old valid ciphertext, orphan files or a token chain for an alternative. Retry from a new authoritative expected ID under bounded caller policy, or return conflict/recovery required. If expected file is missing/corrupt, only explicit caller-authorized validated rebuild can enroll a new record; do not silently reuse an older valid anchor.

## 6. Crash/fault matrix and required tests

These are required future tests, **not executed evidence**. A controllable storage/provider fake must distinguish failures before versus after irreversible effects; real filesystem tests separately check host semantics.

| Interruption/fault point | Allowed recovery/result |
|---|---|
| RNG/nonce reservation, bounds, encode/AEAD, create or partial write | Old exact expected remains recoverable; reservation consumed; temp/orphan grants no use |
| File sync/close, publish-before-directory-sync | No CAS; old expected retained; partial/new entry never selected |
| Directory sync complete, before CAS | Old expected recovers; fully durable new file is still orphan |
| CAS conflict or known pre-attempt unavailability | Old or winner exact trusted ID; loser cannot claim commit |
| CAS dispatched, response lost/timeout | Both files retained; unknown/fenced until exact authoritative resolution |
| CAS acknowledged, before local receipt/cleanup | New exact ID recovers; old may remain; no ordinary rollback error |
| Cleanup unlink/sync failure | Committed success with separate cleanup status; new expected preserved |
| Post-CAS missing/corrupt committed storage | Explicit rebuild/auth failure; never older fallback |
| Provider/store both restored | Durable protection only if provider is independently rollback resistant; process-only test must demonstrate its limitation |
| Invalidation during lease/encryption/publish/CAS/recovery/release | Same-epoch CAS/use fenced; invalidation tombstone persists; stale writer cannot reactivate |

Required discriminating coverage:

- Round-trip every phase (materialize, prepare, bit reverse, each forward/inverse stage, pointwise, scale, integration, Ready/InitialReadyAlias), odd/even logs, zero/tail budgets, exact canonical point encodings for every initialized group cell plus every field/cursor/map/token/generation value, then complete at least two distinct snapshot promotions and compare uninterrupted versus resumed raw components as group elements under common test randomness and independently verify ordinary proofs. Do not compare projective triples for persistence; retain T5's stronger pre-call-cell rollback tests in memory. Test same-generation maintenance saves with increasing revision, zero-delta new generation, overshoot/recycled slots and FullOnly/preparation-mode behavior.
- Reject corruption/truncation at every framing/section boundary, extra bytes, unknown tags/versions/reserved bytes, wrong key/epoch, all five package components separately, original/augmented same-N swaps, every holder/action/session/issuer-scope swap, cross-file header/ciphertext/tag swaps, stale valid authenticated whole-file replacement, wrong expected digest/ID/revision and witness-generation rollback. Oversized lengths/counts/overflow fail before decoded allocation/group work, observed with counters.
- Authenticated malformed fixtures from a test-only sealing helper: noncanonical Fr/point encodings and illegal flags, coordinate-one/public/satisfaction failures, invalid curve/subgroup points, vector lengths, duplicate/zero/unsorted/out-of-domain maps, role duplication/out-of-range/source alias, impossible phase/stream/stage/index/overlay/done/W combinations, absent needed assignments and generation namespace mismatch. Prove validation actually distinguishes these; valid tags cannot bypass it.

## 7. Structural costs, secrecy and limits

With canonical BN254 G1 compressed size 32 bytes and Fr size 32 bytes, pool payload alone derives to `4N*32 +6N*32 =320N` bytes: **335,544,320 bytes (320 MiB)** at N=2^20, before assignment graph, maps, raw proof/header/tag and counters. The frozen codec must verify these canonical sizes. The existing in-memory pool estimate remains **576 MiB**. Saving it needs the additional bounded envelope buffer, plus charged normalization work/scratch; one in-place buffer avoids a second ciphertext copy, not the first buffer. Cold reload needs that buffer plus decoded pool plus public package/tables and assignment/map/validation scratch. If an old live engine remains while replacing it, charge that whole old pool too. These are structural derivations, not observed serialized-size/speed/memory gains, and no universal 2-GiB fit follows.

T5 journals may retain capacity even with zero entries. A checkpoint must include that resident memory in peak accounting but should not persist undo values/marks. Reload can create a clean zero-mark journal with explicitly charged allocation/initialization and future transaction-capacity policy. Allocator spare capacities are process configuration/cost, not authenticated scheduling progress; reconstructing them does not redo FFT work. No `Vec::clone` of the full pool or unbounded all-point batch-normalization is hidden in serialization/validation.

Private plaintext/candidate/decoder buffers and key leases should have explicit ownership and best-effort zeroization of initialized capacity on success/error, with wipe work charged. Do not promise complete wiping of compiler copies, backend key schedules, reallocations, allocator pages, swap, crash dumps, historical ciphertext or storage media. Secret scalar/group/map telemetry is prohibited. Permissions complement encryption; neither unlink nor Rust drop is forward security. AEAD does not hide access/timing/length patterns, authenticate a setup ceremony, establish fresh issuer status or prove arbitrary projection correctness.
