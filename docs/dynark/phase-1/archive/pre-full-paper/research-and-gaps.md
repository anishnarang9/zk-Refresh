## Parameter map and reviewed algebra

**C/H:** Let m=648,156 original constraints, v=643,563 assignment entries including constant one, l=5 public values, and N=1,048,576 padded row domain. The instance slice has six entries including one. N is neither v nor m. The current reduction pads A/B/C row evaluations to N; it does not establish compatibility with a different reduction that adds public-input rows.

For assignment z and change e=z'-z, distinguish:

| Quantity | Meaning | Near-case historical value |
|---|---|---:|
| s_z | Nonzero assignment changes | 5,081 (one public, 5,080 auxiliary) |
| t_A,t_B,t_C | Matrix nonzero entries visited through changed columns, counted with multiplicity | Not measured in the historical report |
| u_A,u_B | Unique touched rows before removing cancellation | 2,390 / 2,370 |
| s_A,s_B,s_C | Nonzero row changes in Ae, Be, Ce after cancellation | 2,390 / 2,370 / 2,370 |
| s_A s_B | Pair visits in each current sparse cross loop if zero rows removed | 5,664,300 |

**D:** A leaf update changes a Merkle computation, not one compiled assignment. Column fanout, coefficient cancellation, and support overlap determine actual cost. `improved_lagrange_sparse_get` sums equal row indices but retains zero sums; worst work follows touched rows even where numerical deltas cancel. Sort/collect costs depend on touched entries as well as support. Do not identify any one of these with the paper's d before reading its definition. New action historical s_z=104,175 and projected pair count 10,502,938,566 per loop rule out blindly extrapolating the near-case cost.

**D/C — personally reviewed by parent:** For interpolation polynomials a,b,c of degree <N over H, Z_H=X^N-1, satisfying assignments obey ab-c=qZ_H. For valid z,z', write changes da,db,dc. Then

`q' - q = (a db + b da + da db - dc) / Z_H`.

As a polynomial quotient operation, dc has degree <N and contributes zero quotient. Its remainder still matters for satisfaction: omitting a separate C-delta quotient is justified only alongside valid original/new assignments. Bilinearity separates two fixed-witness projections and a delta×delta cross term. In the reference, off-diagonal terms use both orientations of `w`, and overlap i=j uses `p[i]`; neither the overlap nor one orientation may be dropped. This reasoning explains the inspected implementation; it is not a substitute for the paper's derivation or soundness theorem.

Groth16 proof bookkeeping also requires current blinding: A_new=A_old+linear_A(e)+(r_new-r_old)delta_G1; analogous B in both groups. C changes by the private linear term, quotient correction, and `s_new A_new - s_old A_old + r_new B1_new - r_old B1_old - (r_new s_new-r_old s_old)delta_G1`. Parent checked these terms against `dynark_prover.rs::update_dynark`; the nearby comment reverses a sign while executable code uses the expression above. The constant coordinate must remain one; public deltas change the verifier's statement, and only auxiliary deltas enter the private linear query.

A safe anchor is immutable: its projection vectors, proof components, r/s, public statement, domain, key and witness generation all refer to the same z0. Replacing only the proof with an updated proof while retaining old projections does not create a valid new anchor. Fully dynamic checkpoints additionally require accumulated corrections relative to a declared generation, complete reconstruction, and an atomic generation swap. Freshly verifying output proofs does not prove those invariants across interruption/reload.

## Security and readiness gates

1. Full revised paper and exact security model are required for paper-complete, fast-algorithm and fully dynamic conformance claims.
2. Production-reachable `test_rng`, unchecked sparse indices, cache/key mismatch and inconsistent domain dimensions are blockers for a production engine; bounded research probes are not production readiness.
3. Cache serialization must authenticate version/identity, bound allocation, protect private projections/blinders, and atomically commit generation metadata. File permissions alone are not authenticated persistence.
4. A new action/holder must select full proving or a separately justified cache transition. A credential's multi-year lifetime is not evidence of hundreds of same-action retries.
5. Original zkey mapping, Solana encoding and actual execution have separate gates. Existing BN254 curve agreement proves none of these.

All performance targets in the master roadmap remain provisional. Unsupported paper details, real credential distribution, stage allocations, cross-action reuse and workload economics must remain explicit gaps, with task-specific ownership in [phase-2-plan.md](phase-2-plan.md).
