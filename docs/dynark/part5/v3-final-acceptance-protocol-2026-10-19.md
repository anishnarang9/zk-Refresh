update between a finalized, unconsumed work request and its Execute. It is a
plausible application stress case, not an observed operator update frequency.
Use final-cohort variant 00, selected before its result, for four fresh paired
Full/Anchor sessions. Counterbalance the order Full/Anchor, Anchor/Full,
Full/Anchor, Anchor/Full. Within each pair require the same issued credential,
exact finalized request-account/action bytes, policy, R0/R1 roots, setup/VK,
loaded ELF, and resulting queue effect. Use separate disjoint ledgers and
fresh owners. A failed, censored, mismatched, or incompletely cleaned pair is
reported and excluded from a paired saving calculation; never replace it
silently.

The primary metric is directly timed outer wall time per mode from initial
application preparation and control fixture through public/private source
preparation, complete witness and relation work, Full proving or Anchor
refresh, ordinary verification, authenticated state catch-up, any persistence
and reload used, clone, finalized Execute, and owned cleanup. Include retries
and failed work. A common immutable seed may be used to preserve exact action
identity; its creation and any circuit-wide setup are measured and disclosed
separately, with the same per-credential or per-action allocation for both
modes. Issuer enrollment and certificate issuance are common prerequisite
costs outside the authorization boundary and are disclosed separately.
DYNARK-specific preparation is always charged to Anchor. Report nested stage
durations as attribution, not as a replacement for the direct outer clock.

qualified; otherwise report CPU as unqualified. Report RSS, storage, transaction
bytes, compute units, fee, and final application effect for each arm.
