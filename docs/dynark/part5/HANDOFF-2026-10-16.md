# Part 5 handoff — October 16, 2026

## Assignment and product standard

Build a credential application in which an eligible X.509/RSA holder proves
authorization for one exact finalized work request, the Solana program checks
current authenticated issuer and revocation state, and the program-owned queue
receives that request exactly once. The principal product objective is to
support **previously unseen credentials within an explicit bounded profile**
through the standard client, without certificate-specific source/offset edits
or a trusted setup for each certificate. Issuer trust and eligibility remain
mandatory. The original fixed `credential-v2-dev` certificate is a development
fixture, not the supported population.

The protected effect is the queue append plus atomic request/nonce
consumption. A receipt, ordinary proof check or offchain work result is not
the application effect. Devnet deployment follows only a reviewable package
and explicit approval of its identities and authorities.
