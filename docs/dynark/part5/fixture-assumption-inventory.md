# Fixture assumptions to remove for reusable credentials

October 15, 2026. This inventory distinguishes the accepted fixed `credential-v2-dev` development fixture from the planned successor profile. It identifies source boundaries; it does not claim the successor has been implemented or qualified.

| Boundary | Current fixture restriction | Product treatment |
| --- | --- | --- |
| `circuits/credential-v2-dev/profile.circom` | Exact 656-byte TBS template; only 298 signed bytes vary. `SERIAL_OFFSET`, `NOT_BEFORE_OFFSET`, `NOT_AFTER_OFFSET`, and `MODULUS_OFFSET` are constants. Issuer/subject names, six extension encodings, AKI, organization and group are fixed bytes. | Keep this immutable for its qualified setup. The successor must select allowed DER shapes and constrain all signed authorization bytes; client offsets must come from structured DER parsing, not manually edited constants or fixture byte search. |
| `circuits/credential-v2-dev/credential.circom` | Fixed TBS length, 16-byte serial, UTCTime 2000–2049, RSA-2048/e65537/SHA-256/PKCS#1 v1.5, two signatures, depth-10 tree and five public fields. | Preserve cryptographic bounds where chosen by the new supported profile. Version any changed TBS shape, policy binding, public schema, leaf domain or setup. Certificate-specific values must remain witness data under one profile setup. |
| `tools/pre_part5/credential_profile.py` | Builds one named issuer and holder, one AKI and organization/group pair. `_unique_offset` finds fixture byte patterns and `admit_tbs` compares against the generated template. | The standard importer must parse canonical DER and derive offsets from structure; return clear unsupported/ineligible errors. Do not require this fixture generator for importing independently created credentials. |
| `circuits/credential-v2-dev/qualification/profile_witness.py` | Synthetic corpus and negative mutations start from the same fixture template and signer objects. | Add multi-holder/issuer corpus and an independent generator, then freeze implementation/artifacts before unseen imports. Keep private keys and raw witnesses out of tracked reports. |
| `circuits/credential-v2-dev/qualification/prover/src/main.rs` | Exact v2 profile, R1CS, WASM and assignment size pins are compile-time constants for the qualified package. | Pin a new manifest once per successor circuit/profile/setup. Never regenerate trusted setup for each certificate; never accept an old package because input names or shape happen to match. |
| `crates/dynark-native-client/src/identity.rs`, `witness.rs`, `worker.rs` | V1 package/profile/mapping digests and fixed witness length are enforced; the Full worker is pinned to the v1 WASM/calculator. | Add explicitly versioned v2 Full, then successor-profile Full adapters. Keep per-credential/action cache and signer state isolated. No v1 mapping or fixed-size assumption transfers to a new relation. |
| `crates/dynark-solana-adapter/src/lib.rs` | Encoded proof and ordinary VK digest currently require exactly five public inputs and six IC points. | Preserve v2 ABI for its exact key. A successor with a signed organization/group policy field needs a separately versioned public schema, ordinary VK digest, encoder and application verifier. |
| `crates/credential-registry/src/` | Identity already includes issuer ID/version and SHA-256(TBS); leaf/tree logic uses the v2 domain and depth. Authority keys and current Head are caller trust. | Retain distinct stable credential identities, issuer versions, slot epochs and tombstones. Bind any successor leaf/domain change exactly; wire an independent authoritative Head and authenticated issuer status into client and program. |
| `program/src/lib.rs`, `program/src/generated_vk.rs` | Receipt prototype uses one issuer hash, historical-root option, short action digest and the old snarkjs VK. No queue/effect or status source. | Use additive versioned request/queue state, multi-issuer enrollment, current-root and fresh status gates, exact action-v2 reconstruction, matching key and atomic effect/replay handling. Keep legacy key separate. |
| `harness/src/fixtures.rs`, `harness/src/solana.rs` | Original v1 fixture and receipt scenarios assume fixed generator/setup and receipt effect. | Retain historical tests. Build new synthetic local application scenarios and report application ELF/queue state, not verifier-only observations as integration results. |

Policy constants still need reasons: the exact algorithm and key size bound circuit complexity; canonical DER and bounded names/extensions avoid ambiguous parsing; purpose OID, key usage and basic constraints express authorization eligibility; validity and issuer enrollment express execution policy. Development OIDs and a 300-second status timeout are test policy only. The successor profile must explain every retained restriction and prove that organization/group changes are bound to an application-checked public policy value. A new supported individual certificate may change issuer, holder, key, serial, dates, AKI, organization and group within the declared profile without source edits or a new trusted setup.
