# Next gate: one fresh request-bound v3 Full proof

The retained nine-pair corpus proves that one public setup can serve varied
certificates. Its actions are synthetic and its signing keys were discarded.
The separate v3 request exporter checks a finalized action but has no
credential or proof. Join these boundaries with **one newly issued development
credential** before connecting Execute to the queue effect. This is a training
case, not the frozen unseen-credential acceptance cohort.

## Inputs and binding

Create a fresh supported-profile issuer and holder with
`cryptography.x509`, retaining the holder signer only in a fresh, owner-only
private directory. Parse the resulting DER through the standard profile
importer. Derive the issuer and policy fields from the signed certificate,
then establish an active depth-10 membership path and its matching root.
The development request must be finalized and immutable. Derive its actual
program/config/issuer/request/queue/head PDAs, ordered account metadata and
canonical action-v2 preimage through the v3 program code. Use the intended
local network genesis, program identity, policy version and circuit identity;
record these identities before signing. The holder signs SHA-256 of the
canonical big-endian 32-byte action field. Verify that signature under the
imported holder modulus before witness work.

The six public fields must be exactly
`[root, issuerHash, notBefore, notAfter, actionHash, policyHash]`, with no
caller-selected substitute. Build the native worker request from those
admitted values and require equality with its independently checked 751
candidate scalars and credential summary. Generate a complete WTNS using the
pinned compiled circuit. Check its exact shape, constant, six public values,
all mapped input coordinates and every R1CS row against the admitted shared
public package. Only then generate a randomized Full proof and verify it
independently with the package's ordinary VK. Encode the six fields plus proof
using the versioned Solana adapter and confirm the same bytes verify through
the v3 program's host verifier.

## Acceptance and limits

A tests-first positive Execute test must show that the resulting proof and
actual finalized request pass preflight and verification, then fail at the
currently disconnected effect gate. After that RED is observed, connect the
reviewed atomic effect helper. Verify exact queue append and request
consumption once, replay rejection, and no state change after a failed
effect. Build and load the actual v3 ELF for the local-validator gate; host
tests alone are insufficient. Record the separate source, setup, ordinary VK,
adapter and ELF hashes, plus bounded preparation/proving/transaction costs.

Keep keys, certificate bytes, witness and private caches out of Git. One
training credential and one Full effect cannot establish corpus-wide Anchor
refresh economics or the frozen unseen-credential gate. A refresh case needs
a second unconsumed request whose old-root proof is rejected before the
new-root Anchor proof is accepted. Own revocation must block current-root
authorization.
