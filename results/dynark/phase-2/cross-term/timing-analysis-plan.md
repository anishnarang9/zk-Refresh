# T4 raw-sample analysis and proposed integration boundary

This is an analysis plan, authored after launch but before inspecting timing samples. It adds no instrumentation, source change, policy or run to the registered schedule.

Use only `kind=measured` field/group pairs from the uninstrumented release process for descriptive timing comparisons. Keep every raw equality/warm-up/diagnostic record and report their counts separately. For each of the14 primary cases, show30 paired values, median accepted/Fast durations, median paired Fast/accepted ratio, p10/p90 paired ratios and the two15-sample order strata. Absolute durations matter: tiny overhead-dominated cases cannot establish useful throughput. A zero denominator is reported as undefined, never an infinite speed claim. For each of4 intermediate cases, show both raw measured pairs and their order; two values are exploratory and do not support a precision/crossover claim. No sample is dropped because its ratio is inconvenient.

Check completed-case/sample counts, every equality flag, both exact pair ledgers, group-call caps, no source/table/executable drift and runner completion/cleanup before accepting an invocation. Timing must account for240,428,847 weighted visits; the separate diagnostic must account for8,551,759, with248,980,606 combined. Report aggregate and per-case support/overlap/FFT/scratch observations. Runtime/support conclusions describe each call's normalized A,B and union, not current changed assignment count alone.

Keep field-kernel and synthetic group results separate. The accepted field comparator receives already canonical sorted rows and preserves its collected separate A/B coefficients; candidate Fast pays normalization/alignment, root conversion and all polynomial work. The isolated comparator stores diagonal products and separates the original interleaved group work. The group microtest retains one public sparse basis per case, uses the equality pair's coefficients without another quadratic pass, compares accepted separate A/B calls against combined-union zero-skipping calls and verifies exact group equality outside clocks. Construction time/calls/retained bytes are paid separately in each process (20,094 construction calls each). Neither this basis nor adding two medians establishes product updating-material/credential latency.

Public weight construction/load/retention, normalized-input generation, returned coefficient retention, sparse basis construction/retention and group summation must remain distinct. Public N1m construction78.664333ms/storage42.911375ms are weight-table-only measurements. The shared tables are equally borrowed; cold/repeated-call accounting adds their paid costs transparently rather than treating prepared material as free. The diagnostic process supplies mutually exclusive phase times, whole observed duration and residual, requested allocation/live/peak/traffic/call observations and sampled RSS as different units. Its one pair per case is excluded from uninstrumented ratios. Short RSS peaks can be missed; requested bytes and conservative structural bounds are not RSS/usable-size claims.

Proposed T5 boundary, for parent review only: a `CrossConfig { method: CrossChoice, limits: CrossLimits }` with explicit `CrossChoice::{Quadratic,Fast}` and a default Quadratic choice. Preserve accepted `UpdatingMaterial::cross` as the direct Quadratic implementation. Add a configured owner boundary such as `UpdatingMaterial::cross_configured(p, normalized_a, normalized_b, config) -> Result<EncodedCross, Error>`, where `EncodedCross` contains the exact G1 contribution and a public aggregate work report. Fast delegates to existing `cross_coefficients(&p.0.domain, &self.0.weights, a, b, Fast, limits)` plus `encode_cross(..., &self.0.lagrange, &self.0.diagonal)`. Material/package trust stays in the owning boundary. Caller rows are canonical sorted, duplicate-free and nonzero; invalid inputs and algebra mismatch never trigger fallback. Do not route the direct comparator through candidate `CrossMethod::Quadratic`, which would add conversion and change its group collection behavior.

Common preflight must count normalized A,B,union,overlap and domain before allocation; check domain/raw/union and structural scratch bounds plus checked quadratic pair work. Owner transaction preflight includes Fast scratch simultaneously with current/staged private state and public material, before RNG/journal/proof work. Dynamic calls use the actual merged accumulated alpha/current B and current A/old accumulated beta supports separately. Only selected Quadratic calls contribute actual pair visits to the invocation cap/telemetry; hypothetical products remain explicit shape estimates. Expose aggregate union/current/accumulated sizes, selected method, preflight scratch, actual pair visits, FFT sizes and group calls. Existing pair-only rejection must not remain as an unconditional proxy for Fast work.

T6 can freeze this forced-method/cap boundary without publishing a selector. After registered observations, propose the smallest held-out confirmation around a real observed bracket, using a fresh full-width coefficient seed and fresh public root-index permutation. At minimum test both bracket sides, an asymmetric case with the same pair product but a larger union (and its transpose), and overlap/diagonal variation. Use30 counterbalanced measured pairs per eligible case with explicit finite total pair/domain/scratch/time budgets. If no reliable bracket is observed, retain direct Quadratic by default and only expose forced Fast; do not invent a crossover. A later selector must use normalized A/B/union/domain and feasibility, preserve direct Quadratic, reject unsupported shapes and remain conservative outside confirmed shape ranges. Exact counts/budget require the observed bracket and new parent approval. Actual credential row supports, same-key credential proofs and end-to-end paid preparation/replay remain later gates.
