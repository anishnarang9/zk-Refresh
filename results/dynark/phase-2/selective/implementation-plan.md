# T7 bounded direct-entry implementation plan

Authoring only, October 10, 2026. Parent accepted the narrow plan; no build or test slot is granted. The accepted dependency formula and P2-D13 reload disposition control this implementation. Existing shared modules, manifests, dependencies and vendor remain read-only.

Files: new `src/selective.rs`, new `tests/private/selective_private.rs` and `tests/private/selective_fixture.rs`, and this owned evidence directory. The sole later shared handshake is `mod selective;` plus public re-exports of SelectiveConfig, SelectiveState, SelectiveStatus, SelectiveProgress, SelectiveLedger, SelectiveStats and SelectiveFullReason. Private conformance registration is cfg(test) within the owned module. No new Error variant is required.

Representation: one shared package/updating material; immutable captured AnchorCore (assignment, full A/B rows, four raw components and r/s); separately owned current assignment/proof/binding; fixed four typed A/B entries with LRU timestamps; at most two staged entries and constant streamed accumulators. The initial current assignment copy and all old/staged validation/result copies are charged. Initial capture performs no eager projection, FFT group output or N-group private allocation. Opaque initial/current commitments domain-separate and bind all PackageIdentity components, holder/action/generation and canonical data. No q, witness, blinder or deterministic proving API is public.

API: create returns (engine, initial ordinary proof, externally owned opaque ledger). begin_update binds the current transition and fully validates its target, derives the frozen-anchor-to-target delta by a complete assignment scan, gathers its exact A/B rows, preflights demand/work/memory/full fallback, and samples both fresh randomizers before scans. advance_update(0) is an exact no-op, including a staged Full result. Positive chunks process N row visits plus two finish actions per miss, then commit a complete proof/cache/LRU/generation together. Cancellation leaves committed state unchanged; tickets and actual performed work remain charged. A ticket is consumed on the first positive action of each entry, not on reservation.

Hard caps: four committed typed entries, two misses per call, eight started attempts per evaluation; no configuration may increase them. Configured checked caps additionally cover current delta, full anchor-relative delta, touched entries, per-call/session row visits/G1 calls/Fr multiplications, correction work, pair visits, chunk actions, full calls and private/global allocation. Small defaults target N<=1024, v<=1024, E<=16384, <=8192 session entry rows, <=8200 entry G1 calls and <=16368 entry field multiplications; operation/allocation16MiB, private32MiB, total64MiB. Tests use N8..256. Exact entry cost is N row visits, N+2 actions, N+1 G1 calls and2(N-1) field multiplications; zero rows still charge visits.

Memory preflight precedes target clone/gather, anchor-relative gathering, output/cross allocation, full capture and randomness. It includes retained frozen/current assignments, A/B fields, old/staged results, BTree touched-row storage, public matrix/key/updating capacities (cached once), full scratch and constant six-entry/accumulator storage. Structural caps are not RSS. Fallible group/canonical output work remains staged before any cache installation. Rollback discards pending objects; committed cells are never overwritten until infallible final installation.

Demand/miss/attempt/entry-work/anchor-support/touch/pair failures choose an explicitly bounded validated Full path before entry scans. Successful fallback retires anchor/cache and latches FullOnly. Invalid identity/statement or unavailable full/memory allowance rejects without silently widening caps. Explicit holder/action invalidation also full-proves. Reload has no serializer: it drops selective reuse on successful fresh validated full proving and retains the same opaque external ledger. Full-after-restart requires that same ledger for the same evaluation; without it a new cold session must be labeled separately. No durable resource-ledger or antirollback claim.

Conformance is authored first: eager and independent polynomial entry oracles, full/common-r/s raw equality, ordinary verification/wrong-public rejection, both reductions and N8..256, C-only/public layouts, demand/diagonal/overlap/cancellation/reversal/accumulation, cache/LRU/hits/misses/third miss/fifth demand/eighth attempt/ninth refusal, bounded chunks/zero/cancel/late fault, both entropy failures, tiny preallocation caps, FullOnly suffix and invalidation/reload loss. These source-authored tests are not called passing or red-verified until a parent-granted queue run. The finite test manifest must count quadratic oracles before execution (<=1m/case, <=20m invocation); preserve every failed trial.
